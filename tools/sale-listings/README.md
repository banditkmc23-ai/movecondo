# ประกาศขาย / Sale listings

MoveCondo ตอนนี้มีคอนโดให้เช่าเป็นหลัก ส่วนประกาศขายอ่านจากไฟล์ข้อมูลด้านล่าง เมื่อมีประกาศในไฟล์นี้ หน้า `/buy/` และหน้าห้องขายจะถูกสร้างให้อัตโนมัติ ถ้ายังไม่มีรายการ หน้าเหล่านั้นจะแสดงสถานะว่างพร้อมปุ่ม LINE ให้เจ้าของลงประกาศ

Sale listings are data-driven. Do not invent or publish example listings as real. An empty `listings` array keeps the Buy pages in the empty state.

## ไฟล์ที่เกี่ยวข้อง / Files

| ไฟล์ | หน้าที่ |
| --- | --- |
| `data/sale-listings.json` | แหล่งข้อมูลหลัก (array `listings`) |
| `images/sale/<slug>/` | รูปของแต่ละประกาศ เช่น `1.webp`, `2.webp` |
| `tools/build-sale-pages.py` | สร้างหน้า `/buy/`, `/buy/<slug>/`, `/type/<kind>/` และอัปเดต `const SALE_LISTINGS` ใน `assets/app.js` |
| `tools/build-agent-files.py` | อัปเดต sitemap และ llms (จะเรียกสคริปต์ด้านบนให้) |

อย่าใส่ประกาศตัวอย่างลงใน `data/sale-listings.json` จนกว่าจะพร้อมเผยแพร่จริง

## สคีมา / Schema

`data/sale-listings.json` ต้องเป็นออบเจ็กต์ที่มีคีย์ `listings` เป็นอาร์เรย์ รายการที่พร้อมเผยแพร่มีฟิลด์ดังนี้

**จำเป็น / Required**

| ฟิลด์ | ชนิด | ความหมาย |
| --- | --- | --- |
| `slug` | string | ใช้ใน URL เท่านั้น เช่น `/buy/noble-state-39-1-bed/` ใช้ตัวพิมพ์เล็ก a-z, 0-9 และขีดกลาง **ห้ามเป็นรหัสห้อง และห้ามแสดงในหน้าเว็บ** |
| `propertyType` | string | หนึ่งใน `condo` · `house` · `land` · `office` · `warehouse` · `other` |
| `project` | string | ชื่อโครงการหรือทรัพย์ |
| `area` | string | ย่านเป็นภาษาไทย เช่น `พร้อมพงษ์` |
| `salePrice` | integer | ราคาขายเป็นบาท (เช่น `7500000` แสดงผลเป็น ฿7,500,000) |
| `photos` | string[] | path จากรากเว็บ ต้องขึ้นต้นด้วย `images/sale/` และไฟล์ต้องมีอยู่จริง |
| `descriptionTh` | string | คำอธิบายภาษาไทย (ห้ามมีข้อมูลเจ้าของ เบอร์โทร รหัสห้อง ข้อความเรื่องสัตว์เลี้ยง หรือ LINE ID) |
| `descriptionEn` | string | คำอธิบายภาษาอังกฤษ (กฎเดียวกัน) |
| `lastVerified` | string | วันที่ตรวจข้อมูลล่าสุด `YYYY-MM-DD` |

**แนะนำ / Recommended**

| ฟิลด์ | ชนิด | ความหมาย |
| --- | --- | --- |
| `areaSlug` | string | slug ย่านที่มีอยู่แล้วใน `areas/` เช่น `phrom-phong` |
| `station` | string | สถานีใกล้สุด เช่น `BTS พร้อมพงษ์` |
| `stationDistanceM` | integer | ระยะทางถึงสถานีเป็นเมตร เช่น `450` |
| `bedrooms` | integer | จำนวนห้องนอน (`0` = สตูดิโอ) เว้นว่างได้ถ้าเป็นที่ดิน |
| `size` | number | พื้นที่ตารางเมตร เก็บทศนิยมได้ เช่น `34.74` |
| `floor` | string | ชั้นจริง เช่น `"12A"` หรือ `"4"` แสดงในหน้าเว็บเป็น ชั้น 12A |

**ทางเลือก / Optional**

| ฟิลด์ | ชนิด | ความหมาย |
| --- | --- | --- |
| `areaEn` | string | ชื่อย่านภาษาอังกฤษ ถ้าไม่ใส่ ระบบใช้ค่า `area` |
| `stationEn` | string | ชื่อสถานีภาษาอังกฤษ |
| `bathrooms` | integer | จำนวนห้องน้ำ |
| `lat`, `lng` | number | พิกัดสำหรับ JSON-LD เท่านั้น ไม่ต้องใส่ถ้าไม่ชัวร์ |
| `published` | boolean | ถ้าเป็น `false` จะไม่ถูกเผยแพร่ (สำหรับฉบับร่าง) |
| `status` | string | ค่าเริ่มต้นถือว่าพร้อมเผยแพร่ ค่า `draft` / `sold` / `hidden` จะถูกข้าม |
| `rentRoomSlug` | string | ใส่เฉพาะเมื่อประกาศขายนี้เป็นห้องเดียวกับประกาศเช่าที่มีอยู่แล้ว เช่น `"mc-001"` ดูหัวข้อด้านล่าง |
| `saleWithTenant` | boolean | ตั้งเป็น `true` เฉพาะเมื่อขายพร้อมผู้เช่าจริง ระบบจะติดป้าย **ขายพร้อมผู้เช่า** (อังกฤษ: **Sold with tenant**) |
| `leaseEndDate` | string | วันสิ้นสุดสัญญาเช่าปัจจุบัน `YYYY-MM-DD` ใส่ได้เมื่อ `saleWithTenant` เป็น true และมีวันที่จริง |
| `currentRentPerMonth` | integer | ค่าเช่าปัจจุบันเป็นบาทต่อเดือน ใส่ได้เมื่อ `saleWithTenant` เป็น true และมีตัวเลขจริง **ห้ามเดา** |
| `transferCosts` | object | ใครออกค่าใช้จ่ายในการโอน ดูหัวข้อด้านล่าง ใส่เฉพาะรายการที่เจ้าของให้มา |

ห้ามใส่ชื่อเจ้าของ เบอร์โทร LINE ID เลขห้อง (unit number) หรือรหัสห้องในไฟล์นี้ถ้าจะไปโชว์บนหน้าเว็บ สคีมาไม่มีฟิลด์สำหรับข้อมูลเหล่านั้นโดยเจตนา

## วิธีเพิ่มประกาศขาย 1 รายการ / How to add one listing

1. คัดกรองรูปก่อนลง ห้ามมีใบหน้า เบอร์โทร ป้ายชื่อ เอกสาร หรือเงาสะท้อนในกระจก ลายน้ำชื่อเอเจนต์หรือช่องทางติดต่อให้เบลอ หรือตัดรูปนั้นออก
2. ตั้ง `slug` ที่อ่านรู้เรื่อง ไม่ซ้ำ และไม่มีรหัสห้อง เช่น `noble-state-39-1-bed`
3. วางรูปไว้ที่ `images/sale/<slug>/` ชื่อ `1.webp`, `2.webp`, … (เรียงตามลำดับที่อยากให้แสดง) จะมีไฟล์ thumb ชื่อ `1-th.webp` ก็ได้ แต่ไม่บังคับ
4. เพิ่มออบเจ็กต์ลงใน `listings` ภายใน `data/sale-listings.json`
5. จากรากรีโป รัน

   ```bash
   python3 tools/build-sale-pages.py
   python3 tools/build-agent-files.py
   ```

   สคริปต์แรกจะผิดพลาดทันทีถ้าฟิลด์ไม่ครบ รูปไม่เจอ ลิงก์ห้องเช่าไม่ถูกต้อง หรือมีข้อความที่ห้าม
6. เปิดตรวจ `/buy/` และ `/buy/<slug>/` แล้วคอมมิตพร้อมรูป แล้วพุชขึ้น `main`

แท็บซื้อบนหน้าแรกจะชี้ไปที่ `/buy/` การค้นหาภายใต้แท็บซื้อจะไปหน้านี้ (หรือหน้าห้องขายถ้ามีรายการที่ตรง) หมวด คอนโด ใต้แท็บซื้อไปที่ `/buy/` หมวดอื่นไปที่ `/type/house/` ฯลฯ พร้อม `?intent=buy`



## ค่าใช้จ่ายในการโอน / Transfer costs

ใส่ฟิลด์ `transferCosts` เมื่อเจ้าของบอกแล้วว่าผู้ซื้อและผู้ขายใครออกค่าอะไร **ห้ามใส่ตัวเลขประมาณ หรืออัตรากฎหมายที่เจ้าของไม่ได้ให้มา** รายการที่ไม่มีในข้อมูลจะไม่ถูกแสดง

ฟิลด์ย่อยที่ใช้ได้ (ใส่เฉพาะที่มีข้อมูลจริง):

| ฟิลด์ | ความหมาย |
| --- | --- |
| `transferFee` | ค่าธรรมเนียมการโอน |
| `specificBusinessTax` | ภาษีธุรกิจเฉพาะ |
| `stampDuty` | ค่าอากรแสตมป์ |
| `withholdingTax` | ภาษีหัก ณ ที่จ่าย |
| `note` / `noteEn` | หมายเหตุเพิ่มเติม (ไทย / อังกฤษ) |

แต่ละรายการเป็นออบเจ็กต์ที่บอกสัดส่วนฝั่งผู้ซื้อและผู้ขาย ได้ทั้งเปอร์เซ็นต์และจำนวนเงินเป็นบาท (ใส่ได้ทั้งคู่หรืออย่างใดอย่างหนึ่ง):

- `buyerPercent` / `sellerPercent` — เปอร์เซ็นต์ (0–100)
- `buyerBaht` / `sellerBaht` — จำนวนเงินเป็นบาท (จำนวนเต็ม)

ตัวอย่างของ Noble State 39 (ข้อมูลจากเจ้าของ ใช้ในไฟล์จริงได้): ผู้ซื้อและผู้ขายออกค่าธรรมเนียมการโอนคนละ 50%

```json
"transferCosts": {
  "transferFee": { "buyerPercent": 50, "sellerPercent": 50 }
}
```

ตัวอย่างถ้ามีทั้งเปอร์เซ็นต์และจำนวนเงิน หรือมีรายการอื่นด้วย (อย่าคัดลอกตัวเลขสมมตินี้ลงไฟล์จริง):

```json
"transferCosts": {
  "transferFee": { "buyerPercent": 50, "sellerPercent": 50 },
  "specificBusinessTax": { "sellerPercent": 100 },
  "note": "ข้อความที่เจ้าของให้มาเท่านั้น"
}
```

ส่วนนี้แสดงเฉพาะในหน้าละเอียด หัวข้อ **ค่าใช้จ่ายในการโอน** (อังกฤษ: **Transfer costs**) ไม่โชว์ในการ์ด

## ขายพร้อมผู้เช่า / Sold with tenant

ถ้าทรัพย์ขายพร้อมผู้เช่าจริง ให้ใส่ `"saleWithTenant": true` เท่านั้น อย่าทำเครื่องหมายนี้ถ้ายังไม่มีผู้เช่า

ถ้ารู้ค่าเช่าปัจจุบันหรือวันสิ้นสุดสัญญา ค่อยใส่ `currentRentPerMonth` และ/หรือ `leaseEndDate` **ห้ามเดาราคาหรือวันที่**

```json
"saleWithTenant": true,
"currentRentPerMonth": 25000,
"leaseEndDate": "2027-04-30"
```

เว็บจะติดป้าย **ขายพร้อมผู้เช่า** / **Sold with tenant** บนการ์ดและหน้าละเอียด รายการประเภทนี้อยู่ในแท็บซื้อพร้อมประกาศขายทั่วไป

## ห้องที่มีทั้งขายและเช่า / A room offered for both sale and rent

ถ้าห้องเดียวกันมีทั้งราคาขายและราคาเช่าจริง ให้เชื่อมประกาศขายกับห้องเช่าที่มีอยู่แล้วด้วยฟิลด์ `rentRoomSlug` เท่านั้น ระบบจะติดป้าย **ขาย / เช่า** (อังกฤษ: **Sale / Rent**) แสดงทั้งสองราคา และมีลิงก์ข้ามระหว่างหน้าขายกับหน้าเช่า

### สิ่งที่ต้องทำ (Webba)

1. ตรวจให้ชัวร์ว่าเป็นห้องเดียวกันจริง ไม่ใช่แค่โครงการเดียวกัน และประกาศเช่านั้นเผยแพร่แล้วใน `data/listings.json` พร้อมราคาเช่าจริง (เช่น ห้อง `mc-001`)
2. ในออบเจ็กต์ประกาศขาย เพิ่มแค่ฟิลด์นี้:

   ```json
   "rentRoomSlug": "mc-001"
   ```

   ใช้ slug ตัวพิมพ์เล็กของห้องเช่า (`mc-` ตามด้วยตัวเลข) ให้ตรงกับโฟลเดอร์ `rooms/<slug>/`
3. **ห้ามใส่ราคาเช่าเอง และห้ามมีฟิลด์ `rentPrice` ในไฟล์ต้นทาง** สคริปต์สร้างหน้าจะดึงราคาเช่าจากประกาศเช่าให้เอง ห้ามเดาราคา
4. ถ้าไม่ใช่ห้องเดียวกัน หรือยังไม่มีประกาศเช่าในระบบ **อย่าใส่ `rentRoomSlug`** ประกาศขายจะแสดงเป็นขายอย่างเดียว (เช่น Noble State 39 ชั้น 12A ตอนนี้เป็นประกาศขายอย่างเดียว เพราะยังไม่ได้ยืนยันว่าเป็นห้องเดียวกับห้องเช่าห้องใด)
5. จากรากรีโป รันคำสั่งเดิม

   ```bash
   python3 tools/build-sale-pages.py
   python3 tools/build-agent-files.py
   ```

   ถ้า `rentRoomSlug` ไม่ตรงกับห้องเช่าที่เผยแพร่แล้ว มีราคาเช่าจริง และมีหน้า `rooms/<slug>/` สคริปต์จะหยุดทันที ไม่สร้างป้ายและไม่เดาราคา ห้องเช่าหนึ่งห้องลิงก์กับประกาศขายได้เพียงรายการเดียว
6. ตรวจว่า:
   - ห้องนี้ขึ้นทั้งแท็บ **เช่า** และแท็บ **ซื้อ**
   - การ์ดและหน้าละเอียดทั้งสองฝั่งมีป้าย **ขาย / เช่า** พร้อมราคาขาย (เช่น ฿7,500,000) และราคาเช่า (เช่น 21,000 บาท/เดือน)
   - มีลิงก์ **ดูประกาศขาย** / **ดูประกาศเช่า** (อังกฤษ: See the sale listing / See the rental listing)
   - JSON-LD ของทั้งสองหน้ามีทั้งข้อเสนอขาย (`Sell`) และให้เช่า (`LeaseOut`)
7. คอมมิตเฉพาะเมื่อข้อมูลเป็นของจริง ห้ามใส่ประกาศตัวอย่างหรือราคาสมมติลงใน `data/sale-listings.json`

เมื่อลิงก์ถูกต้อง ระบบจะ:

- คัดลอกราคาเช่าจาก `data/listings.json` ตอนสร้างหน้า แล้วใส่ `rentRoomSlug` + `rentPrice` ใน `SALE_LISTINGS` ของ `assets/app.js` (เฉพาะรายการที่ลิงก์ได้จริง)
- แพตช์หน้าห้องเช่า `rooms/<slug>/` ด้วยบล็อกที่หุ้มด้วย `<!--mc-sale-rent-->` (ป้าย ราคา ลิงก์ข้าม และ Offer ขายใน JSON-LD) ถ้าเลิกเป็นห้องขาย+เช่า สคริปต์จะลบบล็อกนี้ออกเอง

## ตัวอย่างสคีมา / Schema example

ตัวอย่างด้านล่างเป็นรูปแบบฟิลด์ (อ้างอิง Noble State 39 ซึ่งตอนนี้เป็นประกาศขายจริงแล้ว) **อย่าใส่ `rentRoomSlug` ในรายการนี้** จนกว่าจะยืนยันว่าเป็นห้องเดียวกับประกาศเช่าห้องใดห้องหนึ่ง และมีราคาเช่าจริง

```json
{
  "listings": [
    {
      "slug": "noble-state-39-1-bed",
      "propertyType": "condo",
      "project": "Noble State 39",
      "area": "พร้อมพงษ์",
      "areaSlug": "phrom-phong",
      "areaEn": "Phrom Phong",
      "station": "BTS พร้อมพงษ์",
      "stationEn": "BTS Phrom Phong",
      "stationDistanceM": 450,
      "bedrooms": 1,
      "size": 34.74,
      "salePrice": 7500000,
      "floor": "12A",
      "photos": [
        "images/sale/noble-state-39-1-bed/1.webp",
        "images/sale/noble-state-39-1-bed/2.webp"
      ],
      "descriptionTh": "คอนโด 1 ห้องนอน ขนาด 34.74 ตร.ม. ที่ Noble State 39 ย่านพร้อมพงษ์ ใกล้ BTS พร้อมพงษ์ ประมาณ 450 เมตร",
      "descriptionEn": "A 1-bedroom condo of 34.74 sq.m. at Noble State 39 in Phrom Phong, about 450 m from BTS Phrom Phong.",
      "lastVerified": "2026-11-17"
    }
  ]
}
```

Noble State 39 ชั้น 12A เป็นประกาศขายบนเว็บแล้ว (ขายอย่างเดียว ไม่มี `rentRoomSlug`) ค่าธรรมเนียมการโอนเป็นผู้ซื้อ 50% ผู้ขาย 50% ตามที่เจ้าของบอก ใส่ใน `transferCosts.transferFee` ของรายการนี้ได้เลย
